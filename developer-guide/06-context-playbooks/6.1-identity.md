# 6.1 Identity & Access — playbook

How to implement the Identity & Access context. This is the foundational context — every other context calls `AuthorizationPort` (declared by Tenancy but consumes `User.id` from here), every event records an actor, and every request flows through a Session.

> **Read first**: [handoff §4.1 Identity & Access](../../handoff/04-bounded-contexts/4.1-identity.md), [`design/identity.md`](../../design/identity.md), [ADR-0009](../../decisions/0009-identity-and-external-idp.md), [ADR-0021](../../decisions/0021-pure-bpp-no-storefront.md).

## Entities

### `User`

| Field | Type | Notes |
|---|---|---|
| `id` | `UserId` (branded opaque) | Internal; the cross-context reference key |
| `external_subject_id` | `ExternalSubjectId` | IdP `sub`; immutable; unique |
| `email` | `Email` | IdP-canonical; refreshed on each sign-in |
| `email_verified_at` | `Date \| null` | From IdP `email_verified` claim |
| `display_name` | `LocalizedText` | IdP-canonical; refreshed on each sign-in (single-locale source, stored as `LocalizedText` with `id` key) |
| `preferred_locale` | `BCP47Tag` | Platform-owned (mirrored from IdP at provisioning; mutable thereafter) |
| `avatar_url` | `Url \| null` | Platform-owned (mirrored from IdP at provisioning; mutable thereafter) |
| `status` | `'Active' \| 'Disabled'` | Lifecycle |
| `created_at`, `updated_at` | `Date` | |
| `disabled_at` | `Date \| null` | Set on transition to Disabled |
| `pii_scrubbed_at` | `Date \| null` | Set when right-to-erasure runs (per [ADR-0015](../../decisions/0015-pii-and-right-to-erasure.md)) |

**Invariants:**
- `external_subject_id` is unique across all Users.
- `email` is unique among `Active` users (case-insensitive).
- `email_verified_at` must be non-null for action gates (create org, accept invitation, etc.).
- `display_name.entries` must contain the `id` key.

**Lifecycle:** `Active` ⇄ `Disabled`. No deletion (per [§5.5 of handoff](../../handoff/05-cross-cutting.md)). PII scrubbing per [§5.6](../../handoff/05-cross-cutting.md).

### `Session`

| Field | Type | Notes |
|---|---|---|
| `id` | `SessionId` | Internal opaque |
| `token` | `SessionToken` | Opaque random value; signed cookie carries this |
| `user_id` | `UserId` | Owner |
| `active_org_id` | `OrgId \| null` | The session's current Active Org per [§5.1.5 of handoff](../../handoff/05-cross-cutting.md) |
| `active_store_id` | `StoreId \| null` | The session's current Active Store; must belong to `active_org_id` if both set |
| `created_at` | `Date` | |
| `last_used_at` | `Date` | Updated on each request |
| `expires_at` | `Date` | Default: 30 days idle |
| `device_label` | `string \| null` | Best-effort User-Agent identification |
| `last_ip` | `string \| null` | Redacted in logs per PII catalog |
| `terminated_at` | `Date \| null` | Set on sign-out / sign-out-everywhere |

**Invariants:**
- A `Session` with `terminated_at` set cannot be used. Requests carrying it are rejected.
- `expires_at > created_at`.
- `active_store_id` requires `active_org_id` set; mismatch → rejection.

## Ports declared

| Port | Purpose | Implemented by |
|---|---|---|
| `UserRepositoryPort` | Persistence for `User` aggregate | `DrizzleUserRepository` (this context's `infrastructure/`) |
| `SessionRepositoryPort` | Persistence for `Session` | `DrizzleSessionRepository` |
| `IdpClientPort` | Outbound OIDC operations (build auth URL, exchange code for tokens, validate ID token, fetch userinfo) | `OidcIdpAdapter` (wraps `openid-client`) |

Plus this context **provides** to others:

| Port | Consumed by | Why |
|---|---|---|
| `IdentityUserPort` | Tenancy (for member listing UI) | Resolves `User.id` → `{ display_name, avatar_url, status }` for read-side display |

The `IdentityUserPort` interface lives in **Tenancy**'s `application/ports/external/` (caller-declared per [§4.10 of `04-conventions.md`](../04-conventions.md)); Identity implements an adapter in its own `infrastructure/adapters/`.

## Use cases

In implementation order (within this context):

| # | Use case | Inputs | Notes |
|---|---|---|---|
| 1 | `SignIn` | OIDC callback params (`code`, `state`) | Exchanges code for tokens; validates ID token; JIT-provisions or refreshes the `User`; creates a new `Session`; sets signed cookie. **Idempotent on `state` to handle browser-double-submit.** |
| 2 | `GetCurrentUser` | (none — uses session) | Returns the current `User` for the request's session. |
| 3 | `SignOut` | (uses session) | Marks the current `Session.terminated_at`; clears cookie. Idempotent. |
| 4 | `SignOutEverywhere` | (uses session) | Marks all `Session`s for the user as terminated. Idempotent. |
| 5 | `UpdateProfile` | `{ preferred_locale?, avatar_url? }` | Updates only platform-owned fields. IdP-canonical fields are read-only. |
| 6 | `DisableUser` (System Admin) | `{ user_id, reason }` | Sets `User.status = Disabled`, `disabled_at`. Terminates all sessions for the user. Emits `identity.user_disabled`. |
| 7 | `ReactivateUser` (System Admin) | `{ user_id }` | Sets `status = Active`. |
| 8 | `ScrubUser` (right-to-erasure) | `{ user_id, by_actor, reason }` | Cross-context orchestration per [§5.6.2 of handoff](../../handoff/05-cross-cutting.md). Walks all contexts via scrub ports; scrubs PII in place; scrubs `source_envelope` PII via `audit_pii_scrubber` role. Idempotent. Emits `identity.user_pii_scrubbed`. |

### Use case envelope highlights

- **`SignIn` is special.** It runs before a session exists — the use-case envelope's per-request actor scope is *not yet populated*. `SignIn` resolves the actor inside its body and binds the resulting session to the response.
- **All other use cases use a session-derived actor**, including `SignOut` (the session itself is the authorization).
- **`DisableUser` / `ReactivateUser` / `ScrubUser` are System-Admin only** — `requireCapability('user.disable')`, `'user.reactivate'`, `'user.scrub'`.
- **`ScrubUser` is the only multi-context orchestration** in this context. Use hand-coded compensation per [§5.3.3 of handoff](../../handoff/05-cross-cutting.md).

## Events emitted

| Event | Payload (key fields) | Category | Notes |
|---|---|---|---|
| `identity.user_provisioned` | `{ user_id, external_subject_id, email, display_name }` | identity_session | Emitted on first JIT provision |
| `identity.user_disabled` | `{ user_id, reason, by_actor }` | identity_session | |
| `identity.user_reactivated` | `{ user_id, by_actor }` | identity_session | |
| `identity.user_profile_updated` | `{ user_id, changes }` | identity_session | |
| `identity.user_pii_scrubbed` | `{ user_id, by_actor, reason }` | identity_session | Per [§5.6 of handoff](../../handoff/05-cross-cutting.md) |
| `identity.session_created` | `{ session_id, user_id, device_label }` | identity_session | Emitted by `SignIn` |
| `identity.session_terminated` | `{ session_id, user_id, reason }` | identity_session | `'sign_out' \| 'sign_out_everywhere' \| 'user_disabled' \| 'expired'` |

Category drives Audit retention bucket (per [§4.7 of handoff](../../handoff/04-bounded-contexts/4.7-audit.md)) — `identity_session` defaults to ~1 year.

Note: `identity.authorization_denied` is emitted by **Tenancy** (because Tenancy owns `AuthorizationPort`), not by this context, even though the namespace says `identity.*`.

## Events subscribed

None in Phase 1. Identity is a producer-only context at this phase.

## Migration sketch

`migrations/0002__identity.sql`:

```sql
CREATE TYPE user_status AS ENUM ('active', 'disabled');

CREATE TABLE users (
  id text PRIMARY KEY,
  external_subject_id text NOT NULL UNIQUE,
  email text NOT NULL,
  email_verified_at timestamptz,
  display_name jsonb NOT NULL,                  -- LocalizedText.entries
  preferred_locale text NOT NULL DEFAULT 'id',
  avatar_url text,
  status user_status NOT NULL DEFAULT 'active',
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  disabled_at timestamptz,
  pii_scrubbed_at timestamptz
);

CREATE UNIQUE INDEX idx_users_email_active
  ON users (lower(email)) WHERE status = 'active';

CREATE TABLE sessions (
  id text PRIMARY KEY,
  token text NOT NULL UNIQUE,                   -- opaque
  user_id text NOT NULL REFERENCES users(id),
  active_org_id text,                           -- no FK; cross-context reference
  active_store_id text,                         -- no FK; cross-context reference
  created_at timestamptz NOT NULL DEFAULT now(),
  last_used_at timestamptz NOT NULL DEFAULT now(),
  expires_at timestamptz NOT NULL,
  device_label text,
  last_ip text,
  terminated_at timestamptz
);

CREATE INDEX idx_sessions_user_active
  ON sessions (user_id) WHERE terminated_at IS NULL;
```

**Notes**:
- `active_org_id` / `active_store_id` are **not** foreign-keyed (cross-context reference per [§2.6 of handoff](../../handoff/02-principles.md)).
- `device_label` and `last_ip` are PII-tagged; must be in the redacting logger's mask list and the scrub catalog.

## Cross-context integration

| Direction | Detail |
|---|---|
| **Provides** | `IdentityUserPort` (read-side User lookup) — consumed by Tenancy |
| **Consumes** | `AuthorizationPort` (from Tenancy) — used by all admin use cases |
| **Events consumed by** | Audit (broadly, for AuditRecord ingestion) |

In Phase 1, `AuthorizationPort` exists as a stub with hardcoded role grants. Real matrix-driven authorization arrives with Phase 2 / Tenancy.

## Implementation order (within this context)

1. **Entities + value objects** in `domain/`.
2. **Repositories** (port + Drizzle adapter) for User and Session.
3. **`IdpClientPort`** + OIDC adapter (smallest possible — `getAuthUrl`, `exchangeCode`, `getUserinfo`).
4. **`SignIn`** — exercises JIT provisioning + session creation.
5. **`GetCurrentUser`** — exercises session resolution from cookie.
6. **`SignOut`** and **`SignOutEverywhere`**.
7. **`UpdateProfile`**.
8. **`DisableUser`** / **`ReactivateUser`** (System Admin path; can wait if no admin UI for it yet).
9. **`ScrubUser`** — last, because it requires every other context to have a `*PiiScrubPort` adapter (lands in Phase 7).

## Test checklist

Per [`07-testing.md`](../07-testing.md):

**Domain tests** (§7.3):
- [ ] `User` invariants (email format, display_name has `id` key)
- [ ] `Session` invariants (`expires_at` > `created_at`, terminated state)
- [ ] Status transitions (`Active` ↔ `Disabled`)

**Application tests** (§7.4) — one per use case:
- [ ] `SignIn` happy path (new user JIT-provisioned + session created + event emitted)
- [ ] `SignIn` returning user (no new user; profile refreshed from IdP)
- [ ] `SignIn` rejected when `email_verified` claim is false
- [ ] `GetCurrentUser` returns null when session expired
- [ ] `SignOut` is idempotent
- [ ] `DisableUser` terminates all sessions for the user
- [ ] `UpdateProfile` rejects writes to IdP-canonical fields
- [ ] `ScrubUser` is idempotent across cross-context scrub calls

**Infrastructure tests** (§7.5):
- [ ] `DrizzleUserRepository` round-trip
- [ ] `DrizzleSessionRepository` round-trip + transaction rollback
- [ ] `OidcIdpAdapter` against a stub IdP — happy path, expired token, invalid signature

**Interface tests** (§7.6):
- [ ] `POST /auth/sign-in` (OIDC callback) sets cookie, returns user
- [ ] `GET /me` returns 401 without cookie, returns user with valid cookie
- [ ] `POST /auth/sign-out` clears cookie

## Gotchas

- **Never store passwords.** Authentication is the IdP's job. No `password`, `password_hash`, no recovery flows in BPP code.
- **`email_verified_at` is trusted from the IdP.** Don't re-verify; the IdP claim is authoritative.
- **JIT provisioning matches by `external_subject_id`, not by email.** Email can change at the IdP; `sub` is immutable.
- **A `User.email` change is recorded in `email`, not as a new User.** The User identity is `id`, never the email.
- **`display_name` is single-locale at source** (the IdP's `name` claim) but stored as `LocalizedText` with the `id` key — keeps the type uniform with other LocalizedText fields and makes future multi-locale display painless.
- **Multi-IdP linking is deferred** ([§7.2.1 of handoff](../../handoff/07-open-issues.md)). Don't model `ExternalIdentity` as a separate entity in v1.
- **`Session.token` is the **secret value***; `Session.id` is the internal identifier. They're not the same. The cookie carries `token`; queries by `token` look up the row. Use `id` for foreign references; never expose `token` outside the cookie.
- **`active_org_id` / `active_store_id` are session-level**, not user-level. A user can be in different active contexts in different sessions (different devices).
- **`SignIn` is the only use case that runs without a pre-existing actor.** Everything else inherits the actor from the session.
- **Session expiry sweep is operational** — a background job soft-terminates sessions past `expires_at`. Not part of this context's domain logic.
