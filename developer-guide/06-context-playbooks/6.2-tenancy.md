# 6.2 Tenancy — playbook

How to implement the Tenancy context. This is the largest non-integration context — it owns the Organization → Store hierarchy, invitations, role assignments, the capability matrix that gates the entire application, and Store lifecycle (which drives Beckn republication).

> **Read first**: [handoff §4.2 Tenancy](../../handoff/04-bounded-contexts/4.2-tenancy.md), [`design/tenancy.md`](../../design/tenancy.md), [ADR-0003](../../decisions/0003-store-lifecycle-and-state-machine.md), [ADR-0010](../../decisions/0010-invitation-account-reconciliation.md), [ADR-0018](../../decisions/0018-organization-tenancy.md), [ADR-0019](../../decisions/0019-manual-catalog-republication.md).

## At a glance

| Aspect | Detail |
|---|---|
| Phase landed | [Phase 2](../05-phases.md) — Tenancy |

## Entities

### `Organization`

| Field | Notes |
|---|---|
| `id`, `slug` | `slug` unique platform-wide; URL-encoded |
| `name`, `description` | `LocalizedText` |
| `org_owner_user_id` | Single Owner; transferable |
| `status` | `Active \| Suspended` (rarely used; Orgs persist) |
| Timestamps | |

### `OrganizationMember`

| Field | Notes |
|---|---|
| `id`, `org_id`, `user_id` | |
| `role` | `OrgOwner` or `OrgMember` |
| `joined_at` | When the invitation was accepted |
| `removed_at` | Set when removed; record retained (per [§5.5 of handoff](../../handoff/05-cross-cutting.md)) |

**Invariant:** exactly one `OrganizationMember` per `(org_id, user_id)` with `removed_at` null. A removed member can be re-invited (creating a new `OrganizationMember`).

### `OrganizationInvitation`

| Field | Notes |
|---|---|
| `id`, `org_id` | |
| `email` | Target — case-insensitive |
| `token` | Opaque single-use; non-guessable |
| `status` | `Pending \| Accepted \| Declined \| Revoked \| Expired` |
| `issued_by_user_id` | |
| `issued_at`, `expires_at` | |
| `decided_at` | Timestamp of terminal transition |
| `accepted_by_user_id` | Set on acceptance |

**Lifecycle:** state machine per [ADR-0010](../../decisions/0010-invitation-account-reconciliation.md). One-way to terminal states.

### `Store`

| Field | Notes |
|---|---|
| `id`, `slug`, `org_id` | `slug` unique within `org_id` |
| `name`, `description` | `LocalizedText` |
| `currency` | `ISO4217Code`; **immutable** after first Active product |
| `supported_locales` | Ordered list of `BCP47Tag` (always includes `id`) |
| `status` | `Draft \| Active \| Suspended \| Paused` |
| `submitted_at` | Set when owner submits Draft for activation |
| `created_at`, `updated_at` | |
| `last_status_change_at` | Audit aid; bumps the wire republication |

**Lifecycle:** state machine per [ADR-0003](../../decisions/0003-store-lifecycle-and-state-machine.md). See [`design/tenancy.md`](../../design/tenancy.md) for the full transition matrix.

### `StoreAdminAssignment`

| Field | Notes |
|---|---|
| `id`, `org_id`, `store_id`, `user_id` | |
| `assigned_by_user_id` | |
| `assigned_at` | |
| `unassigned_at` | Set when removed; record retained |

**Invariant:** the `user_id` must be an `Active` `OrganizationMember` of the same `org_id`.

### Capability matrix (runtime data, not an aggregate)

Stored as `(role, capability_name)` rows. Edited at runtime only by System Admins. Backing for `AuthorizationPort.requireCapability`.

| Port | Consumed by | Why |

## Use cases

### Org-scoped

| # | Use case | Capability | Notes |
|---|---|---|---|
| 1 | `CreateOrg` | (any authenticated User can create their own Org) | The creator becomes `OrgOwner`. |
| 2 | `UpdateOrg` | `org.update` | Edit name, description, slug. Slug change is a hard write — links break. |
| 3 | `TransferOrgOwnership` | `org.transfer_ownership` | Two-step: initiate by current Owner; accept by new Owner. Use case is split: `InitiateOrgOwnershipTransfer` + `AcceptOrgOwnershipTransfer`. (Listed as one row for brevity.) |
| 4 | `InviteOrgMember` | `org.invite_member` | Creates `OrganizationInvitation`; sends email via `EmailSenderPort`. |
| 5 | `AcceptInvitation` | (no capability; the token IS the authorization) | Reconciles per [ADR-0010](../../decisions/0010-invitation-account-reconciliation.md). User's email + `email_verified_at` must match. |
| 6 | `DeclineInvitation` | (token-authorized) | Marks `Declined`. |
| 7 | `RevokeInvitation` | `org.invite_member` (the inviter or anyone with that cap in the org) | Marks `Revoked`. |
| 8 | `RemoveOrgMember` | `org.remove_member` | Marks `OrganizationMember.removed_at`. Cascade-removes all `StoreAdminAssignment`s for that user in this org. Cannot remove the Owner (must transfer ownership first). |

### Store-scoped

| # | Use case | Actor | Capability |
|---|---|---|---|
| 9 | `CreateStore` | Owner / Org Member with `store.create` | Auto-creates Default Catalog in Phase 3 (cross-context — Catalog subscribes to `tenancy.store_created`). |
| 10 | `UpdateStore` | Owner / Store Admin | `store.update` |
| 11 | `SubmitStoreForActivation` | Owner | `store.submit_for_activation` — sets `submitted_at`; transitions `Draft` only if all invariants met (name set, contact set, ≥1 Active product — though that last one only matters in Phase 3+). |
| 12 | `PauseStore` | Owner | `store.pause` — `Active` → `Paused`. |
| 13 | `ResumeStore` | Owner | `store.resume` — `Paused` → `Active`. |
| 14 | `ActivateStore` | Platform-scoped | `platform.store.activate` — `Draft` → `Active`. |
| 15 | `SuspendStore` | Platform-scoped | `platform.store.suspend` — any non-Draft → `Suspended`. |
| 16 | `ReactivateStore` | Platform-scoped | `platform.store.reactivate` — `Suspended` → `Active`. |
| 17 | `AssignStoreAdmin` | Org Owner | `org.assign_store_admin` |
| 18 | `UnassignStoreAdmin` | Org Owner | `org.unassign_store_admin` |
| 19 | `RequestStoreRepublish` | Owner / Store Admin | `store.republish` — emits an event the Bridge subscribes to. |
| 20 | `RequestOrgRepublishAll` | Owner | `org.republish_all_stores` — emits an event; Bridge fans out across all stores in the Org. |

### Use case envelope highlights

- **`AcceptInvitation` is the only use case where the actor isn't a session-authenticated User** with a capability gate. The token in the URL is the authorization; the use case checks reconciliation rules instead.
- **`TransferOrgOwnership` is two use cases**, not one — initiate and accept. Don't bundle.
- **`CreateOrg` has no capability gate** — any authenticated User with verified email can create an Org (their own).
- **Store status transitions are guarded by the state machine**, not by ad-hoc `if status === ...` checks. Use the state machine in `domain/state-machines/`.

## Migration sketch

`migrations/0003__tenancy.sql` (abbreviated):

```sql
CREATE TYPE store_status AS ENUM ('draft', 'active', 'suspended', 'paused');
CREATE TYPE invitation_status AS ENUM ('pending', 'accepted', 'declined', 'revoked', 'expired');
CREATE TYPE org_member_role AS ENUM ('org_owner', 'org_member');

CREATE TABLE organizations (
  id text PRIMARY KEY,
  slug text NOT NULL UNIQUE,
  name jsonb NOT NULL,
  description jsonb,
  org_owner_user_id text NOT NULL,             -- cross-context ref to users.id
  status text NOT NULL DEFAULT 'active',
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE organization_members (
  id text PRIMARY KEY,
  org_id text NOT NULL REFERENCES organizations(id),
  user_id text NOT NULL,                       -- cross-context ref
  role org_member_role NOT NULL,
  joined_at timestamptz NOT NULL DEFAULT now(),
  removed_at timestamptz
);

CREATE UNIQUE INDEX idx_org_members_active
  ON organization_members (org_id, user_id) WHERE removed_at IS NULL;

CREATE TABLE organization_invitations (
  id text PRIMARY KEY,
  org_id text NOT NULL REFERENCES organizations(id),
  email text NOT NULL,
  token text NOT NULL UNIQUE,
  status invitation_status NOT NULL DEFAULT 'pending',
  issued_by_user_id text NOT NULL,             -- cross-context ref
  issued_at timestamptz NOT NULL DEFAULT now(),
  expires_at timestamptz NOT NULL,
  decided_at timestamptz,
  accepted_by_user_id text                     -- cross-context ref
);

CREATE INDEX idx_invitations_email_pending
  ON organization_invitations (lower(email)) WHERE status = 'pending';

CREATE TABLE stores (
  id text PRIMARY KEY,
  slug text NOT NULL,
  org_id text NOT NULL REFERENCES organizations(id),
  name jsonb NOT NULL,
  description jsonb,
  currency text NOT NULL,
  supported_locales text[] NOT NULL DEFAULT ARRAY['id'],
  status store_status NOT NULL DEFAULT 'draft',
  submitted_at timestamptz,
  last_status_change_at timestamptz NOT NULL DEFAULT now(),
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (org_id, slug)
);

CREATE TABLE store_admin_assignments (
  id text PRIMARY KEY,
  org_id text NOT NULL REFERENCES organizations(id),
  store_id text NOT NULL REFERENCES stores(id),
  user_id text NOT NULL,                        -- cross-context ref
  assigned_by_user_id text NOT NULL,
  assigned_at timestamptz NOT NULL DEFAULT now(),
  unassigned_at timestamptz
);

CREATE UNIQUE INDEX idx_store_admin_active
  ON store_admin_assignments (store_id, user_id) WHERE unassigned_at IS NULL;

CREATE TABLE capability_grants (
  role text NOT NULL,                           -- 'org_owner', 'org_member', 'store_admin', system-admin roles, etc.
  capability_name text NOT NULL,
  PRIMARY KEY (role, capability_name)
);
```

**Notes**:
- All `user_id` references are NOT foreign-keyed (cross-context reference).
- `last_status_change_at` is updated atomically with `status` — useful for republication timestamps.
- Slugs are unique within `org_id` for stores; globally for organizations.

## Cross-context integration

| Direction | Detail |
|---|---|
| **Provides** | `AuthorizationPort` — every other context's use cases call `requireCapability` against this |
| **Consumes** | `IdentityUserPort` (from Identity) — for member-listing UIs; `EmailSenderPort` (platform-infra) — for invitations |
| **Events consumed by** | Bridge (Phase 6 — `store_status_changed`, `store_republish_requested`, `org_republish_all_requested`); Catalog (Phase 3 — `store_created` triggers Default Catalog creation); Audit (broadly) |

## Implementation order (within this context)

1. **Capability catalog** (`shared/auth/capability-catalog.ts`) — enumerate every capability the Tenancy + later contexts will need. Lock the naming.
2. **`CapabilityMatrixRepository`** + bootstrap seed (the default `(role, capability)` grants).
3. **`AuthorizationPort`** + `AuthorizationService` (the implementation that consults the matrix).
4. **`Organization`** entity + repository + `CreateOrg` use case.
5. **`OrganizationMember`** entity + repository.
6. **Invitation token service** (opaque generation + verification).
7. **`OrganizationInvitation`** entity + repository + `InviteOrgMember` use case + email-sender adapter wired in.
8. **`AcceptInvitation`** + reconciliation rules.
9. **`Store`** entity + state machine + repository + `CreateStore` + `SubmitStoreForActivation`.
10. **Platform-scoped Store transitions** (`ActivateStore`, `SuspendStore`, `ReactivateStore`).
11. **Owner-scoped Store transitions** (`PauseStore`, `ResumeStore`).
12. **`StoreAdminAssignment`** + assignment use cases.
13. **Republication requests** (`RequestStoreRepublish`, `RequestOrgRepublishAll`).
14. **`TransferOrgOwnership`** (two-step).
15. **Background job**: invitation expiry sweep (emits `tenancy.invitation_expired`).

**Domain tests**:
- [ ] Store state machine — every legal transition succeeds; every illegal one throws `StoreStatusTransitionNotAllowedError`.
- [ ] Invitation state machine — same.
- [ ] `Organization` invariants (slug format, single Owner).
- [ ] `Store` invariants (currency immutability scaffolding — full enforcement in Phase 3).
- [ ] State-machine property tests for Store and Invitation (per [§7.9 of `07-testing.md`](../07-testing.md)).

**Application tests** — sample of must-haves:
- [ ] `CreateOrg` creates Org with creator as Owner and emits `org_created`.
- [ ] `InviteOrgMember` creates invitation, sends email, emits event (assert with fake `EmailSenderPort`).
- [ ] `AcceptInvitation` happy path → creates `OrganizationMember`, marks invitation `Accepted`.
- [ ] `AcceptInvitation` rejected when User's email doesn't match.
- [ ] `AcceptInvitation` rejected when `email_verified_at` is null.
- [ ] `AcceptInvitation` rejected when invitation expired.
- [ ] `AcceptInvitation` is idempotent (already-accepted invitation returns existing Member).
- [ ] `CreateStore` rejected when User lacks `store.create` capability for the active Org.
- [ ] `PauseStore` rejected when status ≠ `Active`.
- [ ] `SuspendStore` rejected for Owner (Platform-scoped only).
- [ ] `SuspendStore → Paused` is forbidden (no laundering moderation).
- [ ] `AuthorizationPort.requireCapability` raises `AuthorizationDeniedError` AND emits `identity.authorization_denied`.

**Infrastructure tests**:
- [ ] Drizzle round-trips for every entity.
- [ ] `email_pending` partial unique index works as expected.
- [ ] `store_admin_assignments` partial unique index allows re-assignment after unassign.

**Interface tests**:
- [ ] URL slug mismatch (`/orgs/foo/...` when session's `active_org_id` resolves to bar) returns 403.
- [ ] `POST /orgs` creates Org and sets cookie's `active_org_id`.
- [ ] `POST /invitations/:token/accept` works for any authenticated User; rejects with typed error on reconciliation failure.

## Gotchas

- **Store ownership lives at the Org level**, not per-store ([ADR-0018](../../decisions/0018-organization-tenancy.md)). Don't model a `Store.owner_user_id`.
- **Invitation acceptance reconciliation** ([ADR-0010](../../decisions/0010-invitation-account-reconciliation.md)): User email matches (case-insensitive) AND `email_verified_at` is non-null AND User is `Active` AND invitation is `Pending` and not expired. Any failure → typed error; no manual claim flow.
- **`StoreStatusChanged` is the single trigger** for Bridge republication on lifecycle changes. Don't add other signals.
- **`Suspended` → `Paused` is forbidden**. Owners cannot launder platform moderation through a voluntary pause.
- **Default Catalog auto-creation isn't this context's responsibility**. Catalog subscribes to `tenancy.store_created` in Phase 3 and creates its own Default Catalog. Tenancy emits the event; nothing more.
- **`AuthorizationPort` is the single place capability decisions live.** Don't sprinkle `if (user.role === ...)` checks. Always go through the port.
- **The capability matrix is runtime data.** Code only defines the *catalog* of capabilities (what's possible). Grants are seeded once and edited by System Admins in-band (Phase 8 UI).
- **Slug changes break URLs.** Surface this in the Admin UI when an Org owner edits a slug. Same for Store slugs.
- **Invitation expiry is operational** — a background job marks expired invitations. Don't compute expiry on read; persist the state transition so it's auditable.
- **Manual republication should be rate-limited** ([ADR-0019](../../decisions/0019-manual-catalog-republication.md)). Operational concern, not architectural — implement at the HTTP middleware level.
- **`Organization.org_owner_user_id` is the single source of truth for Org ownership.** `OrganizationMember.role = OrgOwner` is a derived view; keep them in sync via the use case, or model Owner-as-Member explicitly. Pick one approach (the playbook leans "single source of truth on Organization; Member.role is materialized for query convenience") and stick to it.
- **`identity.authorization_denied` emitted from Tenancy** has the `identity.*` wire namespace by design — it's about an actor's denied attempt, even though Tenancy's `AuthorizationPort` is what emits it.
