# 6.5 Promotion — playbook

How to implement the Promotion context. Small and focused — code-based vouchers, store-scoped, validated and recorded by Order at quote / confirm / cancel time. The Promotion context never mutates Orders; it just provides validation and the authoritative redemption log.

> **Read first**: [handoff §4.5 Promotion](../../handoff/04-bounded-contexts/4.5-promotion.md), [ADR-0007](../../decisions/0007-pricing-tax-and-vouchers.md), [ADR-0008](../../decisions/0008-localization-and-localizedtext.md).

## At a glance

| Aspect | Detail |
|---|---|
| Phase landed | [Phase 4](../05-phases.md) — Inventory + Promotion (parallel) |
| Owns | `Voucher`, `VoucherUsage` |
| Scope | Store-scoped only in v1 (no platform-wide promotions) |
| External systems | None |
| Cross-context users | Order (validates at `/select` / quote-time; records at `/confirm`; reverts at cancel-from-Confirmed) |
| First migration | `0006__promotion.sql` |

## Entities

### `Voucher`

| Field | Notes |
|---|---|
| `id` | Internal opaque |
| `store_id` | Cross-context ref |
| `code` | `VoucherCode` — case-insensitive; unique within store |
| `description` | `LocalizedText` |
| `discount_type` | `'percentage' \| 'fixed_amount'` |
| `discount_value` | Decimal (percentage) OR `Money` (fixed) |
| `max_total_uses` | Integer; optional (null = unlimited) |
| `max_uses_per_user` | Integer; optional |
| `starts_at`, `expires_at` | Optional validity window |
| `minimum_cart_value` | `Money`; optional |
| `status` | `'active' \| 'disabled'` (owner toggle) |
| `current_total_uses` | Derived from `VoucherUsage` count; cached for fast limit checks |
| `created_at`, `updated_at` | |

**Derived states (not stored, computed at read):**
- `Expired`: `expires_at < now`
- `Exhausted`: `current_total_uses >= max_total_uses`

A voucher is **usable** iff: `status = 'active'` AND not Expired AND not Exhausted AND `now >= starts_at` (if set).

**Invariants:**
- `code` unique within `store_id` (case-insensitive).
- `discount_value > 0`.
- If `discount_type = 'percentage'`, `discount_value <= 100`.
- `description.entries.id` set.
- `expires_at > starts_at` if both set.

### `VoucherUsage` (the authoritative redemption log)

| Field | Notes |
|---|---|
| `id` | |
| `voucher_id` | |
| `user_id` | The Beckn buyer's mapped identifier (BAP-supplied via Order); nullable since buyers aren't Users ([ADR-0021](../../decisions/0021-pure-bpp-no-storefront.md)) |
| `order_id` | Cross-context ref to Order |
| `applied_at` | Timestamp |
| `discount_applied_amount` | `Money` — actual discount computed at quote time |
| `reverted_at` | Nullable; set if `RevertVoucherUsage` was called |
| `revert_reason` | Optional |

`VoucherUsage` rows are **append-only-with-revert** — never deleted; reverted usages stay for audit but don't count against limits.

## Use cases

### Store Admin authoring

| # | Use case | Capability | Notes |
|---|---|---|---|
| 1 | `CreateVoucher` | `voucher.create` | Validates code uniqueness within store; sets `status = 'active'`. |
| 2 | `UpdateVoucher` | `voucher.update` | Editing `code` after creation is allowed but flagged in UI. |
| 3 | `DisableVoucher` | `voucher.disable` | Active → Disabled. |
| 4 | `EnableVoucher` | `voucher.enable` | Disabled → Active. |
| 5 | `ListVouchers` | `voucher.read` | Per-store list. |
| 6 | `GetVoucherDetail` | `voucher.read` | Single voucher + derived state + usage count. |
| 7 | `GetVoucherUsageHistory` | `voucher.read.usage` | Filterable by date / order_id. |

### Cross-context (called by Order via `PromotionVoucherPort`)

| # | Use case | Behavior |
|---|---|---|
| 8 | `ValidateVoucher(code, store_id, buyer_ref, cart_total) → ValidatedDiscount \| TypedError` | Looks up voucher; runs all gates (usable, store match, cart minimum, per-user limit); returns discount or typed error. **Does not mutate.** |
| 9 | `RecordVoucherUsage(voucher_id, buyer_ref, order_id, discount_applied) → VoucherUsage` | Atomic with `current_total_uses` increment. Re-runs limit check inside the transaction to handle races. |
| 10 | `RevertVoucherUsage(voucher_usage_id, reason)` | Sets `reverted_at`. Limits recompute (next count of usages where `reverted_at IS NULL`). Emits event. Idempotent. |

### Use case envelope highlights

- **`ValidateVoucher` is read-only.** It can be called many times during a single quote flow (e.g., re-validation at /init); no side effects.
- **`RecordVoucherUsage` is the ONLY write to `VoucherUsage`.** It must run inside a transaction that re-checks limits — concurrent confirms of the same voucher must not exceed `max_total_uses`.
- **`RevertVoucherUsage` is idempotent.** Calling it twice on the same usage is a no-op.
- **Per-user limit enforcement uses `user_id IS NOT NULL` count.** If `buyer_ref` isn't a known User (BAP buyer), the count uses whatever identifier Order passes — operational specifics belong to Order.

## Migration sketch

`migrations/0006__promotion.sql`:

```sql
CREATE TYPE voucher_status AS ENUM ('active', 'disabled');
CREATE TYPE discount_type AS ENUM ('percentage', 'fixed_amount');

CREATE TABLE vouchers (
  id text PRIMARY KEY,
  store_id text NOT NULL,                       -- cross-context ref
  code text NOT NULL,
  description jsonb NOT NULL,
  discount_type discount_type NOT NULL,
  discount_value numeric(10,2) NOT NULL,        -- percentage OR Money minor units (stored as numeric for both)
  discount_value_currency text,                 -- nullable; set for fixed_amount only
  max_total_uses int,
  max_uses_per_user int,
  starts_at timestamptz,
  expires_at timestamptz,
  minimum_cart_value_amount bigint,
  minimum_cart_value_currency text,
  status voucher_status NOT NULL DEFAULT 'active',
  current_total_uses int NOT NULL DEFAULT 0,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX idx_vouchers_store_code
  ON vouchers (store_id, lower(code));

CREATE TABLE voucher_usages (
  id text PRIMARY KEY,
  voucher_id text NOT NULL REFERENCES vouchers(id),
  user_id text,                                  -- nullable; cross-context ref
  order_id text NOT NULL,                        -- cross-context ref
  applied_at timestamptz NOT NULL DEFAULT now(),
  discount_applied_amount bigint NOT NULL,
  discount_applied_currency text NOT NULL,
  reverted_at timestamptz,
  revert_reason text
);

CREATE INDEX idx_voucher_usages_voucher_active
  ON voucher_usages (voucher_id) WHERE reverted_at IS NULL;
CREATE INDEX idx_voucher_usages_user
  ON voucher_usages (user_id) WHERE user_id IS NOT NULL AND reverted_at IS NULL;
```

## Implementation order (within this context)

1. **`Voucher`** entity + repository + `CreateVoucher`.
2. **`UpdateVoucher`** + `DisableVoucher` + `EnableVoucher` + listing/detail use cases.
3. **`VoucherValidator`** service (the gates: usable, store, cart minimum, per-user limit).
4. **`DiscountCalculator`** service (applies discount to `base_price`; **tax recomputes on the discounted base**).
5. **`VoucherUsage`** entity + repository.
6. **`ValidateVoucher`** use case (read-only).
7. **`RecordVoucherUsage`** with in-transaction re-check.
8. **`RevertVoucherUsage`** (idempotent).
9. **`PromotionVoucherPortAdapter`** — implements Order's interface.

## Test checklist

**Domain tests**:
- [ ] `Voucher` invariants (code uniqueness checked at construction; discount_value > 0; percentage <= 100).
- [ ] `VoucherValidator` returns correct typed errors for each gate failure.
- [ ] `DiscountCalculator` applies percentage correctly with rounding.
- [ ] `DiscountCalculator` applies fixed_amount correctly (currency must match cart).
- [ ] Tax recomputes on discounted base (GST/VAT-compliant).
- [ ] Derived state computation: Expired (expires_at < now); Exhausted (count >= max_total_uses).

**Application tests**:
- [ ] `CreateVoucher` rejects duplicate code in same store; same code allowed in different stores.
- [ ] `ValidateVoucher` happy path returns `ValidatedDiscount`.
- [ ] `ValidateVoucher` returns typed errors for: not found, store mismatch, disabled, expired, exhausted, not started, cart minimum not met, per-user limit exceeded.
- [ ] `RecordVoucherUsage` increments `current_total_uses` atomically.
- [ ] `RecordVoucherUsage` rejects when limit would be exceeded (re-check inside transaction).
- [ ] `RevertVoucherUsage` is idempotent.
- [ ] After revert, `current_total_uses` query (live count) decreases by 1.

**Infrastructure tests**:
- [ ] Round-trip Voucher + VoucherUsage.
- [ ] `idx_vouchers_store_code` enforces case-insensitive uniqueness within store.

**Concurrency tests**:
- [ ] Concurrent `RecordVoucherUsage` on a voucher with `max_total_uses=1` succeeds for exactly one caller.

## Gotchas

- **One voucher per order in v1.** No stacking. The "no multiple vouchers" rule is enforced at Order, not Promotion — Promotion just validates one at a time.
- **Discount applies to `base_price`, NOT `published_price`.** Tax recomputes on the discounted base. This is GST/VAT-compliant ([ADR-0007](../../decisions/0007-pricing-tax-and-vouchers.md)).
- **Promotion never mutates Order.** It only validates and records. Order owns the Quote shape; voucher application appears in the Quote as a captured snapshot.
- **`current_total_uses` is a cache.** The truth is `count(voucher_usages where reverted_at IS NULL)`. If drift occurs (manual ops, restored backup), recompute from the table.
- **Per-user limits depend on `user_id` being meaningful.** With buyers-not-Users, Order passes whatever identifier the BAP supplies. Documenting this is Order's job; Promotion just enforces the rule using whatever it's given.
- **No platform-wide vouchers in v1.** Store-scoped only. If asked, that's [§7.2.5 of handoff](../../handoff/07-open-issues.md) — explicit deferral.
- **No rule-based promotions** (BOGO, X-for-Y, automatic cart discounts) in v1. Same deferral.
- **`VoucherUsage` is append-only with revert flag.** Don't delete; revert. Audit + financial retention demand this.
- **`code` editing is allowed but breaks shared links.** Surface in Admin UI.
- **Revert on cancel-from-Confirmed is Order's responsibility to trigger.** Promotion just exposes the use case; Order decides when to call.
