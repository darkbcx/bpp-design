# 4.3 Catalog

The Catalog context owns **what a store sells** — Products (in one of four modes), their attributes, variants, components, choice groups, media, categorization, pricing, and the named **Catalogs** that group them. It's the largest context by surface area and the primary input to Beckn projection.

> Backed by: [ADR-0004](../../decisions/0004-store-publication-and-multi-catalog-projection.md) (multi-catalog projection), [ADR-0005](../../decisions/0005-catalog-and-product-modeling.md) (base Product modeling), [ADR-0023](../../decisions/0023-product-composition-and-choice-modeling.md) (four-mode discriminator; Composite + Configurable Products), [ADR-0025](../../decisions/0025-optional-per-variant-sku-and-pattern-b-projection.md) (optional per-variant SKU; Pattern B always), [ADR-0007](../../decisions/0007-pricing-tax-and-vouchers.md) (pricing and tax), [ADR-0008](../../decisions/0008-localization-and-localizedtext.md) (LocalizedText), [ADR-0020](../../decisions/0020-default-catalog-mandatory.md) (Default Catalog mandatory).
> Full entity model: [`design/catalog.md`](../../design/catalog.md).

## Position and ownership

**Owns:**
- `Product` (one of four modes: `Standalone` | `Variant` | `Configurable` | `Composite`)
- `ProductAttribute` (variant-defining attributes; Variant mode only)
- `ProductVariant` (Variant mode only)
- `ProductComponent` (Composite mode only — references other Products/Variants as parts)
- `ChoiceGroup` + `Choice` (Configurable mode only — decision points and their options)
- `Catalog` (the **Default Catalog** and zero-or-more **additional Catalogs** per store)
- `CatalogMembership` (additional Catalogs only; Default is implicit)
- `PlatformCategory` (hierarchical taxonomy, platform-defined)
- `ProductCategoryAssignment`, `Media`

**Cross-context references** (by ID only):
- `Store.id` — every Product / Catalog belongs to exactly one Store.
- `User.id` — only in events (actor attribution).

**Is consumed by:**
- **Inventory** — references the Product or ProductVariant for anchor creation; anchor type is `StockLevel` for Standalone / Variant or `OwnerPurchasability` for Composite / Configurable (per [ADR-0024](../../decisions/0024-inventory-for-composite-and-configurable-products.md)).
- **Promotion** — Voucher application happens in Order against Catalog prices.
- **Order & Fulfillment** — captures Catalog snapshots (price, tax, name, description, and resolved choice/component breakdown) into the Quote.
- **Beckn Bridge** — projects Products as `Resource`s with `resourceStructure` derived from mode (PLAIN / VARIANT / WITH_EXTRAS / COMPOSED / BUNDLE), pricing as `Offer`s, categories per the mapping registry.

## Four product modes (per [ADR-0023](../../decisions/0023-product-composition-and-choice-modeling.md))

A Product is in exactly one of four modes, chosen at creation and **immutable**:

| Mode | Use when… | Structure | Beckn `resourceStructure` |
|---|---|---|---|
| **Standalone** | Single SKU, no variants, no parts, no choices | One Product, sold as-is | `PLAIN` |
| **Variant** | One product family with axis variants (Size × Color, color × storage, tier subscriptions) sharing name / description / category but each with its own stock and optionally its own SKU | One Product with variant-defining attributes; `ProductVariant`s enumerate the chosen combinations. Each Variant may carry an optional own SKU (per [ADR-0025](../../decisions/0025-optional-per-variant-sku-and-pattern-b-projection.md)), `price_override`, `media`, and has its own `StockLevel`. | `PLAIN` parent + `VARIANT` siblings (Pattern B; always) |
| **Configurable** | Build-your-own with required and/or optional choices (e.g., build-your-pizza; custom cake) | One Product with one or more `ChoiceGroup`s, each with `RequiredSingle` / `OptionalSingle` / `OptionalMultiple` semantics. Choices may optionally anchor stock against another Product/Variant (`option_product_ref`). | `WITH_EXTRAS` (all-Optional groups) or `COMPOSED` (any Required group) |
| **Composite** | Packaged multiple SKUs sold as one unit (combo meal, starter kit, paket murah) | One Product with one or more `ProductComponent`s, each referencing a Standalone Product or ProductVariant with a `quantity`. Composition depth = 1 (no nested composites). | `BUNDLE` + `bundleComposition[]` |

**Decision rule for the store (revised per [ADR-0025](../../decisions/0025-optional-per-variant-sku-and-pattern-b-projection.md)):**

Per-variant SKU is no longer a tie-breaker — Variant-mode Variants can carry their own SKU. Choose between Variant and Standalone (one or more) on **family vs. independent** semantics:

| Use **Variant** mode when… | Use multiple **Standalone** Products when… |
|---|---|
| Items share name, description, and category | Items have distinct names / descriptions / categories |
| Items differ along well-defined axes (size, color, capacity) | Items don't share a clean axis structure |
| You want the family to render as a picker UI | You want each item to stand alone |
| You want shared lifecycle (archive the family together) | You want independent lifecycle per item |

For configurators (Configurable) and packaged bundles (Composite), the choice is dictated by the structure itself.

**Modes are mutually exclusive in v1.** No variant bundles (Family Combo S/M/L as native siblings), no configurable variants (per-size extras menus), no nested composites. Workarounds documented in [ADR-0023](../../decisions/0023-product-composition-and-choice-modeling.md) §"Consequences".

## Catalogs within a store (per [ADR-0004](../../decisions/0004-store-publication-and-multi-catalog-projection.md) + [ADR-0020](../../decisions/0020-default-catalog-mandatory.md))

A store has:

- **Exactly one Default Catalog**, auto-created with the store, not deletable. **Mandatory membership**: every Product in the store is automatically and permanently a member. There is no exclusion mechanism. *(Per ADR-0020 — the way to hide a Product from Beckn is to set `status = Archived`.)*
- **Zero or more additional Catalogs** — named, scoped to the store, with **opt-in membership** (products are added explicitly via `IncludeProductInCatalog`).

A Product may be in **the Default Catalog (always) + zero or more additional Catalogs**.

All Catalogs project to Beckn — each as a distinct wire `Catalog` object carrying the same `Provider` (the store). BAPs see distinguishable groupings. See [§3.4.1](../03-beckn-integration.md) for the wire shape.

## Key concepts

### Product

Entity invariants:
- `name` — required; `LocalizedText`; unique within store (uniqueness checked on default-locale `id`).
- `description` — required; `LocalizedText`.
- `mode` — `Standalone` | `Variant` | `Configurable` | `Composite`; immutable.
- `sku` — optional; unique within store if set.
- `status` — `Draft` | `Active` | `Archived`.
- `base_price` — `Money`, tax-excluded (required for `Active`). For Configurable, this is the configurator's starting price (Choice `price_delta`s compose at quote time). For Composite, this is the bundle's own price (typically discounted vs. component sum; component prices are informational).
- `tax_rate` — decimal percentage (required for `Active`). The Product's own rate applies to the whole composed pre-tax price across all modes.
- Derived (cached, auto-recomputed on price/rate change): `tax_amount = round(base_price × tax_rate / 100)`; `published_price = base_price + tax_amount`.
- At least one `ProductCategoryAssignment` required for `Active`.
- Mode-specific `Active` guard: Variant — ≥1 `ProductVariant`; Configurable — ≥1 `ChoiceGroup` with ≥1 `Choice` each; Composite — ≥1 `ProductComponent`.

### ProductVariant (Variant mode only)

- `product_id`, `attribute_values` (one per parent's `ProductAttribute`)
- `sku` — **optional** (per [ADR-0025](../../decisions/0025-optional-per-variant-sku-and-pattern-b-projection.md)); if set, unique within the store in a single namespace shared with `Product.sku`. **Resolution:** the variant's effective SKU is `variant.sku ?? parent.sku ?? null` (use the Application-Layer helper `ResolveVariantSku`).
- `media` (optional; inherits parent's if absent)
- `price_override` (optional; tax-excluded). Variant inherits parent's `tax_rate`.
- No per-variant `tax_rate` — tax category attaches to the Product.

### ProductAttribute (Variant mode)

- `name` — `LocalizedText` (e.g., `{id: "Ukuran", en: "Size"}`)
- `allowed_values` — ordered list; each value has a locale-neutral identifier and optional `LocalizedText` label.

### ProductComponent (Composite mode)

A part of a Composite Product. Per [ADR-0023](../../decisions/0023-product-composition-and-choice-modeling.md).

- `parent_product_id` — the Composite (immutable)
- `component_anchor_ref` — opaque ref to a **Standalone** Product or a **ProductVariant** of a Variant-mode Product. Same opaque-ref shape Inventory uses for `StockLevel`.
- `quantity` — integer ≥ 1; consumed per Composite unit
- `display_order`

Forbidden: referencing a Composite (no nesting) or a Configurable; duplicate component refs (use `quantity` to express multiples).

### ChoiceGroup (Configurable mode)

A decision point on a Configurable Product. Per [ADR-0023](../../decisions/0023-product-composition-and-choice-modeling.md).

- `product_id` — the Configurable (immutable)
- `name` — `LocalizedText`
- `selection_type` — `RequiredSingle` | `OptionalSingle` | `OptionalMultiple`
- `min_selections` / `max_selections` (used by `OptionalMultiple` only)
- `display_order`

### Choice (within a ChoiceGroup)

A single selectable option. Per [ADR-0023](../../decisions/0023-product-composition-and-choice-modeling.md).

- `choice_group_id` — the parent group (immutable)
- `label` — `LocalizedText`
- `price_delta` — optional `Money` (tax-excluded); may be negative
- `option_product_ref` — **optional** opaque ref to a Standalone Product or ProductVariant. When set, selecting this Choice depletes the referenced anchor's stock at order confirm (per [ADR-0024](../../decisions/0024-inventory-for-composite-and-configurable-products.md)). When null, the Choice is a label-only modifier (no stock effect).
- `display_order`

Forbidden: `option_product_ref` pointing to a Composite (recursive resolution) or to a Configurable (choose-then-choose).

### PlatformCategory

- Hierarchical taxonomy (platform-defined; System Admin–managed).
- `name` — `LocalizedText`.
- Status: `Active` | `Deprecated`. Cannot be deleted while assignments reference it.
- Stores assign their Products to platform categories; the Bridge derives Beckn `provider.categories[]` from this taxonomy.

### Media

Ordered list of media references per Product (and optionally per Variant). Storage is an Infrastructure concern; the domain knows only references. `alt_text` is `LocalizedText`.

## Lifecycles

### Product

| From → To | Actor | Guard |
|---|---|---|
| (new) → `Draft` | Owner / Admin | none |
| `Draft` → `Active` | Owner / Admin | ≥1 category assignment + `base_price` + `tax_rate` + mode-specific guard (see below) |
| `Active` → `Archived` | Owner / Admin | none |
| `Archived` → `Active` | Owner / Admin | ≥1 valid (non-deprecated) category + mode-specific guard |

**Mode-specific `Active` guard:**

| Mode | Guard |
|---|---|
| Standalone | (none beyond shared) |
| Variant | ≥1 `ProductVariant` exists |
| Configurable | ≥1 `ChoiceGroup`, each with ≥1 `Choice` |
| Composite | ≥1 `ProductComponent` |

Forbidden: `Active` → `Draft`, any deletion, mode change.

`Draft`: invisible everywhere regardless of catalog membership.
`Active`: visible based on store state + catalog membership + (for additional catalogs) inclusion.
`Archived`: invisible; retained for order history.

### ProductVariant (Variant mode)

No independent state machine — variants belong to their parent Product. Removal allowed only if no order references it; otherwise *retired* (kept but flagged).

### ProductComponent, ChoiceGroup, Choice

No independent state machine — they follow the parent Product's lifecycle. Add/remove/update freely while parent is `Draft` or `Active`; archiving the parent freezes the structure. Removal allowed only if no order line references the entity; otherwise retained for history.

### PlatformCategory

`Active` → `Deprecated`. Deprecated categories remain referenceable for legacy assignments but aren't selectable for new ones. Deletion only when no assignments reference.

### Catalog (additional)

Created / renamed / deleted by store users. Default Catalog: created with store, never deleted.

## Pricing and tax (per [ADR-0007](../../decisions/0007-pricing-tax-and-vouchers.md))

- All monetary values use the `Money` value object: integer minor units + ISO 4217 currency code.
- A store has **one currency**, set at creation, **immutable** once the store has any Active product.
- Stored on Product: `base_price`, `tax_rate`. Derived: `tax_amount`, `published_price`.
- Variants inherit parent's `tax_rate`; only `price_override` is variant-level.
- Per-mode `base_price` interpretation: Standalone / Variant — Product's own list price; Configurable — configurator's starting price (Choice `price_delta`s compose at quote time); Composite — bundle's own price (component prices are informational).
- `Choice.price_delta` (Configurable mode) is added to the configurator's `base_price` pre-tax at quote time; no separate `tax_rate` on choices.
- Quote construction uses these as inputs but is owned by the Order context — no quoted price stored in Catalog.

## Localization (per [ADR-0008](../../decisions/0008-localization-and-localizedtext.md))

`LocalizedText` fields in Catalog: `Product.name`, `Product.description`, `ProductAttribute.name` + value labels, `ChoiceGroup.name`, `Choice.label`, `Media.alt_text`, `PlatformCategory.name`.

Every `LocalizedText` must have an entry for the platform default locale `id`. Reads use `get(locale)` with fallback to default. Uniqueness checks on `Product.name` use the default-locale value.

## Notable rules

- **Cross-store identity is independent.** Two stores selling the same physical SKU maintain two independent Product records. No platform-wide canonical product (per ADR-0005).
- **`Product.mode` is immutable.** A Product that should have been a different mode must be archived and recreated.
- **Modes are mutually exclusive in v1** (per [ADR-0023](../../decisions/0023-product-composition-and-choice-modeling.md)). No combinations: no variant bundles, no configurable variants, no composite configurables. Workarounds documented in the ADR.
- **Variant-mode projection is always Pattern B** (per [ADR-0025](../../decisions/0025-optional-per-variant-sku-and-pattern-b-projection.md)). One PLAIN parent Resource + one sibling VARIANT Resource per `ProductVariant` — regardless of whether any Variant carries an own SKU, price override, or media. Pattern A (`variantMatrix`) is deferred as a future Bridge-only optimization.
- **Single per-store SKU namespace.** `Product.sku` and `ProductVariant.sku` share one uniqueness scope (case-insensitive). A Variant's effective SKU resolves as `variant.sku ?? parent.sku ?? null`.
- **Composite depth = 1.** A Composite's components must be Standalone or Variant Products (`ProductVariant`s) — not other Composites or Configurables.
- **Choice options are stockable only when they need to be.** `Choice.option_product_ref` is optional. Label-only modifiers (no stock effect) are the default; stock-anchored modifiers are an explicit author choice.
- **Categorization is platform-defined**, not store-defined. Store-private organization is served by additional Catalogs, not by per-store categories.
- **All Default Catalog membership is implicit** per [ADR-0020](../../decisions/0020-default-catalog-mandatory.md) — there's no `CatalogMembership` row needed for Default. Only additional Catalogs use explicit inclusion rows.
- **Quote / pricing computation lives in Order**, not Catalog. Catalog supplies snapshots (base price, tax, name, description, and the structural breakdown of components/choices); Order constructs the Quote.

## Out of scope (v1)

- **Variant bundles** (Family Combo S/M/L as native siblings) — deferred per [ADR-0023](../../decisions/0023-product-composition-and-choice-modeling.md). v1 workaround: three separate Composite Products, optionally grouped via an additional Catalog.
- **Configurable variants** (per-size extras menus) — deferred per [ADR-0023](../../decisions/0023-product-composition-and-choice-modeling.md). v1 workaround: one Configurable Product with size and extras as parallel `ChoiceGroup`s.
- **Nested composites** — deferred per [ADR-0023](../../decisions/0023-product-composition-and-choice-modeling.md). v1 workaround: pre-configure the inner composite as a Standalone Product.
- **`FIXED` choice group semantics** (Beckn's spec-grey fourth `selectionType`) — out of scope; use `longDesc` for non-selectable disclosure.
- **Digital vs. physical goods type taxonomy** — assume physical for v1.
- **Search / discovery implementation** (full-text, facets) — read-side index, infrastructure concern.
- **Media storage and file handling** — Infrastructure Layer.
- **Cross-store deduplication for discovery** — search-layer concern; not domain.
- **Sub-roles on Store Admin** (e.g., "catalog editor only") — would extend the matrix.
- **Time-bound list-price changes** (sales windows on the catalog price) — Vouchers approximate this; future work for direct sale-pricing.
